# mk-plugin-hsr

[mk-go](https://github.com/shiroha-a/mk) のサーバープラグイン。利用者が崩壊:スターレイルの UID を登録すると、プロフィールに戦績とショーケースのビルドを表示する。

> **本体の 2.0 以降 (develop ではマニフェストの名前を elythia-plugin.yml に変えたコミットの後) が要る。** 本体の Go のモジュールパスが `github.com/elythia-network/elythia` に変わり、マニフェストの名前が `elythia-plugin.yml` に変わった版に合わせてある。それより前の本体には、タグ `pre-elythia` (本体のモジュールパスを変える前) か `pre-elythia-manifest` (モジュールパスを変えた後、マニフェストの名前を変える前) の版を使う。

データ元は [Enka.Network](https://enka.network/)。認証不要の公開 API を使う。

## 導入

mk-go は**プラグインをビルド時に組み込む**。`plugins/` に置いてビルドし直す。

```bash
# mk-go のリポジトリルートで
cd plugins
git clone https://github.com/shiroha-a/mk-plugin-hsr hsr
cd ..

make build          # plugins/ を走査して取り込む
```

フロントエンドを持つので、**フロントエンドも作り直す**。

```bash
make uds-frontend-build   # 本番構成 (docker-uds)
# または make e2e-frontend-build
```

そのうえで mk-go を再起動する。**再起動しないと画面が変わらない** — mk-go は起動時に一度だけ manifest を読むため。

```bash
make uds-up
```

> **注意**: 配布されている Docker image (`ghcr.io/shiroha-a/mk`) を pull するだけでは使えない。ビルド時組み込みなので、プラグインを使うインスタンスは自分でビルドする必要がある。

導入の一般論は [mk-go の docs/plugins/operating.md](https://github.com/shiroha-a/mk/blob/develop/docs/plugins/operating.md) を参照。

## 使い方

利用者が **設定 → プロフィール** で UID を入力する。9 桁の数字。

登録時に一度だけ取得して存在を確かめるので、UID が間違っていればその場で分かる。以後は 10 分ごとのジョブが期限切れのものだけ取り直す。

表示するには、ゲーム内で**キャラ詳細を公開**しておく必要がある。飾っていないキャラや非公開のアカウントでは、名前と戦績だけになる。

プロフィールでは既定で**ラベル 1 行**しか出さない。他の情報と並ぶ場所なので、開かないうちは縦を占有しない。

## 設定

省略できる。既定で動く。

```yaml
# .config/default.yml
plugins:
  hsr:
    enabled: true
    endpoint: https://enka.network      # 取得元 (テスト用に差し替えられる)
    userAgent: mk-go-plugin-hsr/0.1 (+https://github.com/shiroha-a/mk)
    timeoutSeconds: 10
    language: ja                        # 名前の言語
    masterEndpoint: https://raw.githubusercontent.com/EnkaNetwork/API-docs/master/store/hsr/
```

`language` は `en` / `zh-cn` / `ko` などに変えられる。指定した言語が無ければ英語に落ちる。

## 表示する情報

**プレイヤー**: ニックネーム / 自己紹介 / 開拓レベル / 均衡レベル / サーバー地域 / 環境 / 達成実績数 / 忘却の庭の到達層 / 模擬宇宙のスコア / 所持キャラ・光円錐・遺物・楽曲・書籍の数 / プロフィールアイコン

**ショーケースのキャラ (最大 5 体)**: レベル / 昇格 / 星魂 (解放状況をアイコンで) / 軌跡 (メインスキル 5 つ + 憶霊 + 枝ごとのノードを点灯 / 消灯で) / 光円錐 (名前・レア度・レベル・重畳・基礎値) / 遺物 6 部位 (セット名・強化度・メイン・サブ 4 つ) / **最終ステータス**

サブステータスには**伸びた回数**が付く (`速度 8.9 ×4`)。原神には無い情報で、同じ数値でも「1 回で伸びた」のか「4 回積んだ」のかが分かる。

## リモート利用者

**同じプラグインを入れた mk-go 同士**なら、他インスタンスの利用者のプロフィールにも戦績が出る。相手のインスタンスに取り寄せを頼む形で、経路は mk-go 専用の peer channel (ActivityPub には出ない、mk-go #2537)。

- 相手が同じプラグインを持たなければ何も出ない (Misskey TS などが相手なら常にそうなる)
- **問い合わせは非同期**なので、初めて開いたときは出ない。少し経ってから出る
- 取り寄せた分は 30 分覚える
- 相手に送るのは **username だけ**。誰が見に来たかは送らない
- 相手が返す画像 URL は、こちらのプロキシ経由に貼り替える

相手側は「自分のところの利用者」の分だけ答える。手元にキャッシュしている他所の利用者を又貸しはしない。

## 取得元への配慮

Enka.Network が[利用条件として挙げている](https://github.com/EnkaNetwork/API-docs/blob/master/api_ja.md)ことを守っている。

- **`ttl` を必ず待つ。** 応答が返す `ttl` 秒はキャッシュから返し、期限が切れたものだけ 10 分ごとのジョブで取り直す
- **`User-Agent` を名乗る。** 既定でもインスタンスが分かる形で送る
- **UID を列挙しない。** 取得するのは利用者が自分で登録した UID だけ

画像は Enka から直接読まず、**同一オリジンで中継**する (`/api/plugin/hsr/asset/<path>`)。mk-go の CSP が `img-src 'self'` なので、緩めずに表示するため。**大きいものは縮小してから配る** (後述)。

## 開発

```bash
cd plugins/hsr && go test ./...
```

DB は実 PostgreSQL を使う (`TEST_DB_*` 環境変数)。Enka とマスターデータは `httptest` で差し替えるので、外部には出ない。

テストデータ (`testdata/`) は実際の Enka の応答から 1 体分を抜き出したもので、**手で書いた値ではない**。取得元の形が変わればテストが落ちる。UID とニックネームだけは架空のものに差し替えてある。

### 踏みやすい罠

原神版とは API の癖がかなり違う。公式のドキュメントが無い (API-docs にあるのは原神とゼンレスゾーンゼロだけ) ので、形は実データから起こしている。

- **URL の末尾にスラッシュを付けない** — 原神は `/api/uid/<uid>/` だが、こちらは付けると 308 で飛ばされる。揃えようとすると片方が壊れる
- **`honker_` 付きのマスターを使わない** — `honker_characters.json` は名前のハッシュが `7809981386909966580` → `7809981386909966000` と丸められている (JS の double を経由した跡)。実測でキャラ名が **82 件中 0 件**しか解決しない。接頭辞の無い `avatars.json` なら 95 件すべて引ける
- **最終ステータスは返ってこない** — 原神の `fightPropMap` に当たるものが無いので、キャラ基礎値 + 光円錐 + 遺物 + セット効果 + 軌跡を自分で足す
- **同じステータスが 2 つの名前で来る** — メインは `CriticalDamageBase`、サブは `CriticalDamage`。畳まないと遺物のメイン分が丸ごと落ちる (実測で会心ダメージが 193.6% → 91.5% になった)。ただし `HPBase` は「基礎HP」で別物なので、接尾辞を機械的に剥がしてはいけない
- **`flat` ではなく `_flat`** — アンダースコアが付く
- **`_flat.props` の先頭がメインステータス**、残り 4 つがサブ
- **光円錐の画像はフルアートしかない** — 1 枚 1.8MB あり、小さい版は公開されていない。中継時に縮小してプロセス内にキャッシュしている
- **キャラと光円錐で鍵名の前後が逆** — キャラは `HPBase` / `HPAdd`、光円錐は `BaseHP` / `BaseHPAdd`
- **解放していない軌跡ノードは応答に来ない** — マスター側の定義と突き合わせて初めて「取っていない」と分かる
